# What is an Algorithm?

An <em>Algorithm</em> is a step-by-step logical procedure used to solve a problem.
<br />

## Table of Contents

## Key Types of Algorithms
<br />
**<u>Recursion:</u>**&nbsp;&nbsp;a type of algorithm where a function calls itself with different parameters 
for each call to itself until it reaches a base case.
<br />
**<u>Divide and Conquer:</u>**&nbsp;&nbsp;a type of algorithm that continuously breaks a problem down into smaller, 
sub-problems of the same type, solves those sub-problems, and combines their solutions.
<br />
**<u>Greedy:</u>**&nbsp;&nbsp;a type of algorithm that builds a solution step-by-step; at each step of the algorithm, the
algorithm, faced with a number of options, will pick the option that appears the best at that moment. The goal is to reach
a globally optimal solution through a series of local optimizations.
<br />
**<u>Dynamic Programming:</u>**&nbsp;&nbsp;a type of algorithm that breaks a problem into smaller sub-problems, then
solves each sub-problem only once, and stores the solution of each sub-problem in a data structure.

### ⚜️&nbsp;&nbsp;GCD of Two Numbers
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given two numbers $a$ and $b$, develop an efficient algorithm to find the greatest common divisor (GCD)
between these two numbers.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we will use the Euclidean Algorithm.
<br />
The Euclidean Alogrithm states that given two natural numbers $a$ and $b$, 
$gcd(a, b) = gcd(b, a \pmod{b})$.
The algorithm repeats this process until the value of $b = 0$.
<br />
I have implemented the Euclidean Algorithm using recursion:
<br />
```python showLineNumbers
# Recursive Solution
class Solution:
    def gcd(self, a: int, b: int) -> int:
        if b == 0:
            return a
        
        return self.gcd(b, a % b)
```
<br />
$Time\;Complexity: O(log(min(a, b)))$
<br />
**Explanation:**
<br />
- **The numbers** shrink by at least half at least every two steps.
- **Start:** We begin with the pair $(a, b)$.
- **Step 1:** The new pair becomes $(b, a \pmod{b})$. Let's call the result of $[a \pmod{b}] \rightarrow r_1$. 
So the new pair then becomes $(b, r_1)$.
- **Step 2:** The new pair becomes $(r_1, b \pmod{r_1})$. Let's call the result of $[b \pmod{r_1}] \rightarrow r_2$.
So the new pair then becomes $(r_1, r_2)$.
- We want to prove that $r_1 < \frac{a}{2}$.
- **Case A:** $b <= \frac{a}{2}$. Since $r_1$ is a remainder of a division between $a$ and $b$, 
we can state that $r_1 < b$ and we know that $b <= \frac{a}{2}$; therefore, $r_1 < \frac{a}{2}$.
- **Case B:** $b > \frac{a}{2}$. If $b$ is more than half of $a$, we can state that $b$ can only fit into $a$ exactly one time.
Therefore, the remainder is just the difference: $r_1 = a - b$. Since $b > \frac{a}{2}$, subtracting a number larger than half
of $a$ leaves the result smaller than half of $a$. Therefore, $r_1 < \frac{a}{2}$.
- Therefore, the first number in our pair $a$, always drops to less than half of its size every two steps.
- If you start with a number $X$, you can divide it by 2 a maximum of $log_2(X)$ times before it hits $1$.
- Since it takes a maximum of two steps for guarantee a halving, the maximum number of steps is $2 • log_2(X)$.
- $X$ can be replaced with $min(a,b)$ because the remainder $r$ must always be less than the minimum of the two inputs 
in a division, and so since the remainder $r$ replaces one of the input values, with the other input value being the next 
modulo operation which is less than $r$, $r$ is upper bounded by the minimum of $a$ and $b$.
- **Hence,** the big $O$ time 
complexity is: $O(log(min(a, b)))$.

### ⚜️&nbsp;&nbsp;LCM of Two Integers
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given two integers $a$ and $b$, develop an efficient algorithm to find the least 
common multiple (LCM) of these two integers.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we will use the Euclidean Algorithm to find the greatest common
divisor (GCD) of the two integers and then use this formula: 

$$
lcm\_integer(a, b) = \frac{a\;•\;b}{gcd(a, b)}
$$

Since I have already implemented a recursive version of $gcd(a, b)$ above, so I will not provide it again here.

I have implemented the solution using iterative implementation:
<br />
```python showLineNumbers
# Iterative Solution
class Solution:
    def gcd(self, a: int, b: int) -> int:
        while b != 0:
            a_previous = a
            a = b
            b = a_previous % b
        
        return a
    
    def lcm_integer(self, a: int, b: int) -> int:
        gcd_result = self.gcd(a, b)
        return (a*b) // gcd_result
```
<br />
$Time\;Complexity: O(log(min(a, b)))$
<br />
**Explanation:**
<br />
- **The Euclidean Algorithm** time complexity in the worst-case is $O(log(min(a, b)))$.
This worst-case scenario happens when $a$ and $b$ are consecutive Fibonacci numbers. <br />(See explanation above)
- **The multiplication operation** between $a$ and $b$ takes $O(1)$ time.
- **Dividing** the product by the $gcd(a, b)$ takes $O(1)$ time.
- **Hence,** the big $O$ time complexity is: $O(log(min(a, b)))$.
<br />
$Space\;Complexity: O(log(min(a, b)))\;if\;gcd(a, b)\;was\;implemented\;recursively,

- **For the remaining arithmetic operations**, namely the multiplication of $a$ and $b$, 
and the division of the product with $gcd(a,b)$, 
the algorithm only needs to store a few integer variables resulting in constant auxiliary memory usage regardless of size

### ⚜️&nbsp;&nbsp;LCM of Two Non-Integers
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given two non-integers $a$ and $b$, develop an efficient algorithm to find the least common 
multiple (LCM) of these two non-integers.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we will convert the non-integers into fractions, and then separate
$a$ and $b$ into numerators in denominators. Then we will use the lcm
algorithm for integers explained above to compute the $lcm\_integer(numerator\_a, numerator\_b)$. 
Then we will use the gcd algorithm
to compute $gcd(denominator\_a, denominator\_b)$. Then we will plug the results into this formula:

$$
lcm\_non\_integer(a, b) = \frac{lcm\_integer(numerator\_a, numerator\_b)}{gcd(denominator\_a, denominator\_b)}
$$

Since I have already implemented a recursive version of $gcd(a, b)$ above, so I will not provide it again here.

I have implemented the solution using iterative implementation:
<br />

```python showLineNumbers
# Iterative Solution
from fractions import Fraction

class Solution:
    def gcd(self, a: int, b: int) -> int:
        while b != 0:
            a_previous = a
            a = b
            b = a_previous % b
        
        return a
    
    def lcm_integer(self, a: int, b: int) -> int:
        gcd_result = self.gcd(a, b)
        return (a*b) // gcd_result

    def lcm_non_integer(self, a: float, b: float) -> float:
        a_fraction = Fraction(a)
        b_fraction = Fraction(b)

        numerator_a = a_fraction.numerator
        numerator_b = b_fraction.numerator

        denominator_a = a_fraction.denominator
        denominator_b = b_fraction.denominator

        lcm_numerator = self.lcm_integer(numerator_a, numerator_b)
        gcd_denominator = self.gcd(denominator_a, denominator_b)

        return lcm_numerator / gcd_denominator
```

### ⚜️&nbsp;&nbsp;Is Prime
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an integer $n$, develop an efficient algorithm to determine if it is a prime number or not. 
A prime number is a number greater than 1 that has no positive divisors other than 1 and itself.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;If $n$ is composite (not prime), it can be factored into two numbers $a$ and $b$ such that
$n = a\;•\;b$.<br />If both $a > \sqrt{n}\;and\;b > \sqrt{n},\;then\;a\;•\;b > n$. 
Similarly if $a < \sqrt{n}\;and\;b < \sqrt{n},\;then\;a\;•\;b < n$.<br />Therefore either $a \leq \sqrt{n}\;and\;b \geq \sqrt{n}$,
or $a \geq \sqrt{n}\;and\;b \leq \sqrt{n}$.<br />Either way, at least one of the factors of $n$ must be less than or equal 
to $\sqrt{n}$.
This is good because then we can loop starting from the smallest prime number 2 to $\sqrt{n}$. If there exists such a factor, we
will return $False$. But if after the loop no such factor is found, we will return $True$.
We must also ensure that if $n \leq 1$, we return $False$, as the smallest prime number is 2.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
import math

class Solution:
    def is_prime(self, n: int) -> bool:
        if n <= 1:
            return False

        i = 2
        while i <= math.sqrt(n):
            if n % i == 0:
                return False
            i += 1
        
        return True
```
<br />
$Time\;Complexity: O(\sqrt{n})$
<br />
**Explanation:**
<br />
- **The loop** runs $\sqrt{n} - 1$ times.
- **Hence,** big $O$ time complexity is $O(\sqrt{n})$
<br />
$Space\;Complexity: O(1)$
<br />
**Explanation:**
<br />
- **The algorithm** only needs to store a few integer variables resulting in constant auxiliary memory usage regardless of size
of inputs. 
- **Hence,** big $O$ space complexity is $O(1)$

### ⚜️&nbsp;&nbsp;Check if k<sup>th</sup> bit is set or not
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an integer $n$ and non-negative integer $k$, develop an efficient algorithm to 
check if the $k^{th}$ bit is set or not. If the $k^{th}$ bit is set, then return $True$. Otherwise, return $False$.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we want to use bitwise AND operator. Bitwise AND operator compares two binary
values bit by bit, position by position. If in a given position, both of the bits are $1$, then the resulting bit in that position
is $1$, otherwise it is $0$. We take $n$ and perform bitwise AND operation on $2^k$, because in $2^k$ only the $k^{th}$ bit 
is set. So when the bitwise AND operation is performed, we know that in the result all other bits besides $k^{th}$ bit will be $0$. 
We know that the $k^{th}$ bit is set in $2^{k}$; therefore, the $k^{th}$ bit will be set in the result only if the $k^{th}$
bit is also set in $n$. Otherwise, the $k^{th}$ bit will be $0$. Therefore, if the $k^{th}$ bit is set in the result, 
the value of the result will be $\gt 0$, otherwise the value of the result will be $0$.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
class Solution:
    def check_kth_bit(self, n: int, k: int) -> bool:
        if n&(1<<k) > 0:
            return True
        else:
            return False
```
<br />
$Time\;Complexity: O(1)$
<br />
**Explanation:**
<br />
- **The bitwise** AND operation, shifting bits and comparison with $0$ all take constant time.
- **Hence,** the big $O$ time complexity is $O(1)$
<br />
$Space\;Complexity: O(1)$
<br />
**Explanation:**
<br />
- **The algorithm** only needs to store a few integer variables resulting in constant auxiliary memory usage regardless of size
of inputs. 
- **Hence,** big $O$ space complexity is $O(1)$

### ⚜️&nbsp;&nbsp; Valid Anagram
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given two strings $str1$ and $str2$, develop an efficient algorithm to determine if the two 
strings are anagrams of each other. This means that the two strings are composed of the exact same characters with the 
exact same frequencies, just potentially arranged in a different order. If the two strings are anagrams of each other,
return $True$, otherwise return $False$.
<br />
**<u>Solution:</u>**&nbsp;&nbsp; To solve this problem, the first thing to do is to check if the lengths of $str1$ and $str2$
are equal. If the lengths are not equal, we can immediately return $False$, because the strings cannot have the same
frequency of characters if their lengths are different. Then we create an empty dictionary called $char\_count$. We then
loop through $str1$ character by character and for every character, use $char\_count$ to keep track of the number of times
each character appears in the string $str1$. Then after that loop has completed, we will loop through $str2$ character by
character. If we encounter a character that is not in $char\_count$, we can immediately return $False$, because we know that
$str2$ has a character that is not in $str1$ and so it cannot be an anagram of $str1$. For every character that is in 
$char\_count$, we will subtract $1$ from the character's count in $char\_count$. And if the count for a 
character becomes $0$, we delete that character from the dictionary $char\_count$. After this loop, if the two strings $str1$ 
and $str2$ are valid anagrams, then the dictionary $char\_count$ should be empty in the end. If $char\_count$ is empty,
return $True$; otherwise return $False$.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
class Solution:
    def valid_anagram(self, str1: str, str2: str) -> bool:
        if len(str1) != len(str2):
            return False
        
        char_count = {}

        for character in str1:
            char_count[character] = char_count.get(character, 0) + 1
        
        for character in str2:
            if character not in char_count:
                return False

            char_count[character] -= 1

            if char_count[character] == 0:
                del char_count[character]

        if len(char_count) == 0:
            return True
        else: 
            return False
```
<br />
$Time\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **In the worst-case,** the strings $str1$ and $str2$ have the same length, let us call the length $n$.
- **The algorithm iterates** through each string twice.
- **Hence,** big $O$ time complexity is $O(n)$.
<br />
$Space\;Complexity: O(1)$
<br />
**Explanation:**
<br />
- **There are 256** possible ASCII characters, so at most $char\_count$ can hold 256 key-value pairs, which is independent
of the length of the strings $str1$ and $str2$.
- **Hence,** big $O$ space complexity is $O(1)$.

### ⚜️&nbsp;&nbsp;Binary Search
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given a sorted array of integers $arr$ and a key $k$, develop an efficient algorithm to 
determine if $k$ exists in $arr$, if it does return the index in $arr$ where the $k$ is found; otherwise, return $-1$.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we implement the **Binary Search algorithm**, The key idea is that we need 
to repeatedly divide the search space in half by looking at the middle element of the search space. If the middle element is our 
key then return the index of the middle element. If the middle element is not our key, check if our key is smaller or larger than 
the middle element. If the key is smaller than the middle element, divide the search space in half and keep only the left half 
for further evaluation. If the key is larger than the middle element, divide the search space in half and keep only the right 
half for further evaluation. Keep repeating this process until either we have found the element or there is no more search space 
left to evaluate.
<br />
I have implemented the Binary Search algorithm using recursion:
<br />
```python showLineNumbers
# Recursive Solution
class Solution:
    def binary_search(self, arr: list[int], k: int) -> int:
        if not arr:
            return -1
        
        mid = len(arr) // 2

        if arr[mid] == k:
            return mid
        elif arr[mid] > k:
            return self.binary_search(arr[:mid], k)
        else:
            right_side_index = self.binary_search(arr[mid+1:], k)
            if right_side_index != -1:
                return right_side_index + mid + 1
            else:
                return -1
```
<br />
$Time\;Complexity: O(log\;n)$
<br />
**Explanation:**
<br />
- **At the first step,** the search space is $n$.
- **At the second step,** the search space is $\frac{n}{2}$.
- **At the $\mathbf{k^{th}}$ step,** the search space is $\frac{n}{2^k}$.
- **The recursion stops** when the search space is $1$, meaning $\frac{n}{2^k} = 1$. This simplifies to $n = 2^{k}$.
- **Solving for $\mathbf{k}$** gives $k = log_2(n)$, which means that the algorithm took $log_2(n)$ steps.
- **Therefore,** big $O$ time complexity is $O(log\;n)$.
<br />
$Space\;Complexity: O(log\;n)$
<br />
**Explanation:**
<br />
- **Every time** the recursive function calls itself, a new stack frame is created.
- **At the first step,** the search space is $n$.
- **At the second step,** the search space is $\frac{n}{2}$.
- **At the $\mathbf{k^{th}}$ step,** the search space is $\frac{n}{2^k}$.
- **The recursion stops** when the search space is $1$, meaning $\frac{n}{2^k} = 1$. This simplifies to $n = 2^{k}$.
- **Solving for $\mathbf{k}$** gives $k = log_2(n)$, which means that the algorithm took $log_2(n)$ steps.
- **This means** that there are $log_2(n)$ stack frames created.
- **Therefore**, big $O$ space complexity is $O(log\;n)$.
<br />
I have also implemented the Binary Search algorithm iteratively:
<br />
```python showLineNumbers
# Iterative Solution
class Solution:
    def binary_search(self, arr: list[int], k: int) -> int:
        low = 0
        high = len(arr) - 1

        while low <= high:
            mid = low + (high - low) // 2
            
            if arr[mid] == k:
                return mid
            elif arr[mid] > k:
                high = mid - 1
            else:
                low = mid + 1
        return -1
```
<br />
$Time\;Complexity: O(log\;n)$
<br />
**Explanation:**
<br />

### ⚜️&nbsp;&nbsp;Merge Sort
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an unsorted array of integers, implement the Merge Sort algorithm 
and return the array sorted.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;Merge Sort is an efficient, comparison-based, stable sorting algorithm. It 
divides the array in half and then divides the halves of the array into halves and so on until each half contains only
one element (or is empty). And then the algorithm recombines the halves as sorted by comparing values until it gets back the 
original array in sorted order.
<br />
This algorithm can be implemented recursively and iteratively.
<br />
The recursive solution is that it finds the midpoint of the input array $arr$ and then divides the array into two halves based
on that midpoint. The function then calls itself on the left half and on the right half. The base case is if length of $arr$
is $ \leq 1$, then return. Then lastly it will call an iterative helper function called $merge$ to perform the actual comparison
of elements and merging of the arrays. The iterative function will compare each element of the left half with each element of 
the right half and will append the smaller of the two elements to the resulting sorted array. If the two subarrays are of different 
lengths, any elements left over from one of the subarrays will be appended to the end of the sorted array 
as the leftover elements from the one subarray are larger than all of the elements 
of the other subarray. At the end, return the sorted array.
<br />
I have implemented the recursive solution below:
<br />
```python showLineNumbers
# Recursive Solution
class Solution:
    def merge(self, left_half: list[int], right_half: list[int]) -> list[int]:
        sorted_arr = []
        left_half_index = 0
        right_half_index = 0

        while left_half_index < len(left_half) and right_half_index < len(right_half):
            if left_half[left_half_index] < right_half[right_half_index]:
                sorted_arr.append(left_half[left_half_index])
                left_half_index += 1
            else:
                sorted_arr.append(right_half[right_half_index])
                right_half_index += 1
        
        while left_half_index < len(left_half):
            sorted_arr.append(left_half[left_half_index])
            left_half_index += 1

        while right_half_index < len(right_half):
            sorted_arr.append(right_half[right_half_index])
            right_half_index += 1

        return sorted_arr

    def merge_sort(self, arr: list[int]) -> list[int]:
        # Base Case: arrays with 0 or 1 elements are already sorted, so just return
        if len(arr) <= 1:
            return arr;
        
        # Calculate the midpoint
        mid = len(arr) // 2

        # Recursively divide the array into two halves
        left_half = self.merge_sort(arr[:mid])
        right_half = self.merge_sort(arr[mid:])

        # Merge the arrays back up in sorted order
        return self.merge(left_half, right_half)
```

Now, let us transition to the iterative solution of Merge Sort. In the iterative solution, we want to perform the merge
using a bottom-up approach. Meaning we will start with merging two sub arrays of size 1, and then two subarrays of size 2,
and then two subarrays of size 4 and so on. We will use a variable to maintain the size of the subarrays we are currently

```python showLineNumbers
# Iterative Solution
class Solution:
    def merge(self, arr: list[int], left_index: int, middle_index: int, right_index: int) -> None:
        sorted_subarray = []
        i = left_index
        j = middle_index

        # Compare values
        while i < middle_index and j < right_index:
            if arr[i] <= arr[j]:
                sorted_subarray.append(arr[i])
                i += 1
            else:
                sorted_subarray.append(arr[j])
                j += 1
        
        # Add any leftover values to sorted subarray
        while i < middle_index:
            sorted_subarray.append(arr[i])
            i += 1

        # Add any leftover values to sorted subarray
        while j < right_index:
            sorted_subarray.append(arr[j])
            j += 1
        
        # Copy sorted subarray values over the originals
        for k in range(len(sorted_subarray)):
            arr[left_index + k] = sorted_subarray[k]

    def merge_sort(self, arr: list[int]) -> list[int]:
        size_of_subarray = 1

        while size_of_subarray < len(arr):
            for i in range(0, len(arr), 2 * size_of_subarray):
                # Left subarray [i to middle_index - 1]. Right subarray [middle_index to right].
                left_index = i 
                middle_index = i + size_of_subarray
                right_index = middle_index + size_of_subarray

                # Clamp down value of right
                if right_index > len(arr):
                    right_index = len(arr)

                # Merge subarrays only if second subarray exists
                if middle_index < len(arr):
                    self.merge(arr, left_index, middle_index, right_index)
            
            size_of_subarray *= 2

        return arr
```

### ⚜️&nbsp;&nbsp;Quicksort
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an unsorted array of integers, implement the Quicksort algorithm 
and return the array sorted.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;Quicksort is a highly efficient, comparison-based sorting algorithm. It works by selecting 
an element from the array to act as a baseline. This element is called the "pivot". This can be the first element, the last
element, a random element, or the median. The algorithm then partitions the array by rearranging the elements such that the 
elements smaller than or equal to the pivot are to its left and elements larger than the pivot are to its right. The exact
same steps are then applied to the left and right partitions and to their partitions and so on until the partitions are of 
size $0$ or $1$, which means that the array has been sorted.
<br />
This algorithm can be implemented recursively and iteratively.
<br />
For the recursive implementation, the algorithm uses two pointers. The first pointer $low$ initially points at index $0$
and represents the index where the partition begins. The second pointer $high$ initially points at index $len(arr) - 1$
and represents where the partition ends. The algorithm only runs when low < high. The base case is once $low = high$, there 
is only 1 element in our partition, and when $low \gt high$ there are no elements in our partition, and so the algorithm
returns. Our implementation uses the Lomuto partition scheme, which means the last element of a partition is the pivot.
The algorithm calls the partition function which takes the last element as the pivot, and places the pivot in the correct
position and places all elements smaller than the pivot to be before the pivot and all elements greater than the pivot to 
be after the pivot. It accomplishes this rearrangement of elements by utilizing a loop and a pointer keeping track of the 
highest index of the left partition. Then after the partition is complete, the recursive function calls itself on the left 
partition and calls itself on the right partition. Once the base case is reached, the recursive function returns, and the
sorting is complete. The original function can return $arr$ as the result.
<br />
I have implemented the recursive solution below:
<br />
```python showLineNumbers
# Recursive Solution
class Solution:
    def partition(self, arr: list[int], low: int, high: int) -> int:
        # The pivot is set as the last element of the partition.
        pivot = arr[high]

        # Initial highest index of left partition.
        highest_index_left_partition = low - 1

        # Loop through partition and position elements <= pivot in left partition.
        for partition_iterator in range(low, high):
            if arr[partition_iterator] <= pivot:
                # Increment highest index of left partition.
                highest_index_left_partition += 1
                # Swap elements.
                previous_highest_element_left_partition = arr[highest_index_left_partition]
                arr[highest_index_left_partition] = arr[partition_iterator]
                arr[partition_iterator] = previous_highest_element_left_partition

        # Position pivot such that it is the next element after left partition.
        pivot_index = highest_index_left_partition + 1
        pivot_index_old_value = arr[pivot_index]
        arr[pivot_index] = arr[high]
        arr[high] = pivot_index_old_value

        return pivot_index

    def quicksort_helper(self, arr: list[int], low: int, high: int) -> None:
        # The Base Case: If low == high there is only 1 element in the partition, 
        # if low > high, there are 0 elements in the partition, so return.
        if low == high or low > high:
            return

        # Place pivot in correct position with smaller elements in left partition
        # and greater elements in right partition.
        pivot_index = self.partition(arr, low, high)

        # Recursively call quicksort_helper on left and right partitions
        self.quicksort_helper(arr, low, pivot_index - 1)
        self.quicksort_helper(arr, pivot_index + 1, high)

    def quicksort(self, arr: list[int]) -> list[int]:
        low = 0
        high = len(arr) - 1
        self.quicksort_helper(arr, low, high)
        return arr
```

```python showLineNumbers
# Iterative Solution
class Stack:
    def __init__(self):
        self._items = []

    def is_empty(self):
        return len(self._items) == 0

    def size(self):
        return len(self._items)

    def push(self, item: str) -> None:
        self._items.append(item)
    
    def pop(self) -> str:
        if self.is_empty():
            return None
        else:
            return self._items.pop()

class Solution:
    def partition(self, arr: list[int], low: int, high: int) -> int:

        pivot = arr[high]

        pivot_index_old_value = arr[pivot_index]
        arr[pivot_index] = arr[high]
        arr[high] = pivot_index_old_value

        return pivot_index

    def quicksort(self, arr: list[int]) -> list[int]:
        # stack holds tuples containing indices for partition boundaries
        stack = Stack()

        # low represents lower bound of partition.
        # high represents upper bound of partition. 
        low = 0
        high = len(arr) - 1

        # Push initial partition boundary onto stack
        stack.push((low, high))
        
        # While there are still partitions that need to be processed
        while not stack.is_empty():
            # Retrieve new partition bound values
            low, high = stack.pop()

            # If low < high, this means this partition is of size > 1
            # and so it needs to be processed
            if low < high:
                # Place pivot in correct position with smaller elements in left partition
                # and greater elements in right partition.
                pivot_index = self.partition(arr, low, high)

                # Push partition boundaries of left partition onto the stack
                stack.push((low, pivot_index - 1))
                # Push partition boundaries of right partition onto the stack
                stack.push((pivot_index + 1, high))
        
        return arr
```

### ⚜️&nbsp;&nbsp;Reverse Linked List
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given a pointer to the head node of a singly linked-list, reverse the list in place and return
a pointer to the reversed linked list's head node.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;In this problem, we are presented with a pointer to the head node of the singly linked-list
called $head$. To solve this problem recursively, we set the base case as the following: if $head$ is $null$ or if $head.next$ 
is $null$, return $head$. Next we make a recursive call and pass in $head.next$, which is the next element in the singly 
linked-list and store it in a variable called $new\_head$. We call this variable $new\_head$ because as the reversal of links 
progresses the node that $new\_head$ is pointing at will effectively be the new head node of the portion of the singly 
linked-list that has been reversed so far. Next we reverse the pointer. To do this, we use $head.next.next = head$. What this
is saying is take $head.next$, which is the next node, and make its $.next$ value equal to $head$, effectively 
reversing the pointers direction. The next step is to clean up the old pointer. 
Lastly, we return $new_head$.
<br />
I have implemented the solution recursively below:
<br />
```python showLineNumbers
# Recursive Solution
from typing import Self 

class ListNode:
    def __init__(self, val: int = 0, next: Self = None):
        self.val = val
        self.next = next

class Solution:
    def reverse_linked_list(self, head: ListNode) -> ListNode:
        if not head or not head.next:
            return head
        
        new_head = self.reverse_linked_list(head.next)

        head.next.next = head
        head.next = None

        return new_head
```

And the algorithm visits each node of the singly linked-list once.

<br />
Now that we've discussed how to solve the problem recursively, we will now transition to the iterative solution.
To solve this problem iteratively, we want to step through the singly linked-list and reverse the $.next$ value of each node
one by one. As we step through the singly linked-list, we must maintain a pointer of the previous node called 
$prev\_node$, a pointer of the current node called $curr\_node$, and a pointer of the next node called $next\_node$. 
The algorithm starts with $curr\_node$ set as $head$ and loops while $curr\_node$ is not $null$ and then in that loop the first 
action is to store $curr\_node.next$ inside $next\_node$. The reason why we do this is because we do not want to lose access to 
the rest of the singly linked-list after the $.next$ value of $curr\_node$ has been reversed. Next, we reverse the $.next$ value 
of $curr\_node$ by setting $curr\_node.next = prev\_node$. After the reversal of the $.next$ value of $curr\_node$, we need to 
move the pointers one step forward, that way we can continue reversing the $.next$ values of the remaining nodes. So to 
accomplish this, $prev\_node$ is set to $curr\_node$ and then $curr\_node$ is set to $next\_node$. After this loop completes, 
$curr\_node$ has a value of $null$, and so $prev\_node$ contains the head of the newly reversed singly linked-list. So we return 
$prev\_node$.
<br />
I have implemented the solution iteratively below:
<br />
```python showLineNumbers
# Iterative Solution
from typing import Self

class ListNode:
    def __init__(self, val: int = 0, next: Self = None):
        self.val = val
        self.next = next

class Solution:
    def reverse_linked_list(self, head: ListNode) -> ListNode:
        prev_node = None
        curr_node = head

        while curr_node is not None:
            next_node = curr_node.next
            curr_node.next = prev_node

            prev_node = curr_node
            curr_node = next_node
        
        return prev_node
```

$Space\;Complexity: O(1)$
<br />
**Explanation:**
<br />

- **Hence,** big $O$ space complexity is $O(1)$.

## Hash Table Problems
<br />
### ⚜️&nbsp;&nbsp;Top K Frequent Elements
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an integer array $nums$ and an integer $k$, return the $k$ most frequent elements.
You may return the answer in any order.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we use hash tables. First we will want to create a $num\_to\_count$
hash table. We loop through $nums$ and for every number that we see, in $$num\_to\_count$$ we create a key for that number 
and its value is the number of times that we see the number appear in $nums$. After that loop is complete, we create another 
hash table called $group\_nums\_by\_count$ where for every count, we map it to an array of numbers that has that count. 
Next, we will want to populate $group\_nums\_by\_count$ with values and so we loop through $num\_to\_count$ and for every count, 
we append the corresponding number to the array that the count maps to in $group\_nums\_by\_count$. Then we loop in reverse order 
from $len(nums)$ to $1$ and if $group\_nums\_by\_count$ has a key with that loop counter value, we add the numbers in the 
corresponding array to the $top\_k\_frequent$ array. The reason why we loop in reverse order is because we want to access the 
numbers with the highest count first, since the problem is looking for the $k$ most frequent elements, which are the $k$ 
elements with the highest count. Once the length of the $top\_k\_frequent$ array equals $k$, we return $top\_k\_frequent$. 
After the loop ends, if we have not returned then return $top\_k\_frequent$.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
class Solution:
    def top_k_frequent_elements(self, nums: list[int], k: int) -> list[int]:
        top_k_frequent = []
        nums_to_count = {}
        for num in nums:
            if num not in nums_to_count:
                nums_to_count[num] = 1
            else:
                nums_to_count[num] += 1
        
        group_nums_by_count = {}

        for num, count in nums_to_count.items():
            if count not in group_nums_by_count:
                group_nums_by_count[count] = []
                group_nums_by_count[count].append(num)
            else:
                group_nums_by_count[count].append(num)
        
        for count in range(len(nums), 0, -1):
            if count in group_nums_by_count:
                for num in group_nums_by_count[count]:
                    top_k_frequent.append(num)
                    if k == len(top_k_frequent):
                        return top_k_frequent

        return top_k_frequent
```
<br />
$Time\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **The algorithm** counts frequencies of each number which takes $O(n)$ time since it visits every number once.
- **The algorithm** places elements into buckets based on frequencies of each number which also takes $O(n)$ time 
since it visits every number to count mapping once.
- **The algorithm** iterates backwards extracting the top k most frequent elements, which in the worst-case is $O(n)$
time because if all elements are unique, they will all have count of $1$, which is the last loop counter value in the
loop, and the loop will have iterated $n - 1$ times.
- **Hence,** big $O$ time complexity is $O(n)$.
<br />
$Space\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **The two hash tables** used in the algorithm $num\_to\_count$ and $group\_nums\_by\_count$ store $O(n)$ elements in
the worst case scenario where every number in $nums$ is unique. In $num\_to\_count$ every number in $nums$ will by a key,
each mapping to $1$. In $group\_nums\_by\_count$ $1$ will map to an array containing all numbers in $nums$.
- **Hence,** big $O$ space complexity is $O(n)$.

### ⚜️&nbsp;&nbsp;Subarray Sum Equals K
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an array of integers $nums$ and an integer $k$, return the total number of subarrays 
whose sum equals to $k$. A subarray is a contiguous, non-empty sequence of elements within an array.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we must realize that we are only interested in the total number of 
subarrays whose value sum up to $k$. The specific values of the subarrays are not relevant, so long as the sum equals $k$. 
Therefore, we do not need to store any subarray values. Another point is, we want to examine every subarray of the array, but 
we do not want to examine all of them one by one, because that will require looping through all of the subarrays that begin at 
index $0$, followed by all of the subarrays that begin at index $1$, followed by all of the subarrays that begin at index $2$, 
and so on. And doing so will result in a $O(n^2)$ time algorithm, which is not very efficient. We need a way to examine all of 
the subarrays without actually iterating through to examine them. 
<br />
First we need a variable called $num\_subarrays\_equal\_k$, initially set to $0$, which will store the number of subarrays that 
sum up to $k$. Next, what we can do is loop through $nums$ and examine only the subarrays begin at index $0$. Call each subarray 
$subarray[0, b]$. To evaluate the sum of $subarray[0, b]$, we can use a variable $current\_sum\_of\_subarray$, initially set to 
$0$, and add to it every element of $nums$ that we encounter in our loop. 
<br />
Next, we will want to examine if any of the subarrays of $subarray[0, b]$ sum up to $k$. So then, for every subarray that we 
encounter, we need a data structure that will store sum of each subarray mapped to the number of subarrays that have that sum. 
The reason why we structure it this way is because we only need the sum and the number of times we got that sum from a subarray, 
not any of the subarray values themselves. For key/value mappings, the appropriate data structure is hash table. So for every 
$subarray[0, b]$, we will store in the hash table: its sum mapped to the number of times that sum has occurred. So for a given 
subarray $subarray[0, b]$, for its subarrays that begin at index $0$, we already know what their sum is, because we visited them 
already in our loop and we have the sum to count mapping in our hash table. But what about its subarrays that begin at an index 
greater than $0$? So for this we need to leverage a key insight. The key insight is that a main subarray can be broken up into 
two parts: prefix and suffix. The prefix subarray begins at index $0$ and ends at an index smaller than the largest index of the 
main subarray. The suffix subarray begins at the index after the prefix subarray ends at the end of the main subarray. 
Mathematically, it can be expressed as:
<br />
$$
subarray[0, b] = subarray[0, a] + subarray[a + 1, b]
$$
<br />
In our example, $subarray[0, b]$ is the main subarray, $subarray[0, a]$ is the prefix subarray and $subarray[a + 1, b]$ is
the suffix subarray. So we want to figure out if there exists any suffix subarrays $subarray[a + 1, b]$ that sum up to $k$. 
To do this, we use some reverse logic. Suppose the sum of our $subarray[a + 1, b]$ equals $k$, then this means that if we take 
the sum of $subarray[0, b]$ and subtract $k$ from it, we will get the sum of $subarray[0, a]$. 
Since we have a hash table that stores prefix subarray sums, all we need to do is look in that hash table to see the count for
that subarray sum. For each prefix subarray $subarray[0, a]$ that sums up to that value, there will be a 
corresponding suffix subarray $subarray[a + 1, b]$ that sums up to $k$. Therefore, the number of prefix subarrays $subarray[0, a]$ 
that sum up to the value equals to the number of suffix subarrays $subarray[a + 1, b]$ that sum up to $k$. We will want to add 
this value to $num\_subarrays\_equal\_k$. Continue to iterate this loop until the end of $nums$, and return 
$num\_subarrays\_equal\_k$.
<br />
There is one edge case that we must address. To solve for this edge case, we seed the hash table initially with $\{0:1\}$.
This is to handle the scenario where the main subarray $subarray[0, b]$ sums up to $k$. If $subarray[0, b]$ 
sums up to $k$ then:
$$
subarray[0, a] = k - k = 0
$$
<br />
If we do not seed the hash table with $\{0:1\}$, then the value that $0$ maps to in the hash table will contain the number
of all prefix subarrays up to that point that summed up to $0$, which equals the number of corresponding suffix subarrays that 
sum up to $k$. However, it will not include $subarray[0, b]$. Therefore, it is very important to initially seed the hash table 
with $\{0:1\}$.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
class Solution:
    def subarray_sum_equals_k(self, nums: list[int], k: int) -> int:
        # Keeps track of the number of subarray sums that equal k
        num_subarrays_equal_k = 0

        # Keeps track of the main subarray sum
        current_sum_of_subarray = 0

        # Hash Table mapping prefix subarray sums to the number of prefix subarrays that have that sum
        prefix_subarray_sum_count = {0:1}

        # Loop through nums
        for num in nums:
            # Update the sum of main subarray
            current_sum_of_subarray += num

            # Set suffix subarray sum value to k
            suffix_subarray_sum = k

            # Take main subarray sum and subtract suffix subarray sum from it. Set it as prefix subarray sum.
            prefix_subarray_sum = current_sum_of_subarray - suffix_subarray_sum

            # If there exists such a prefix subarray sum, get its count and add it to result
            if prefix_subarray_sum in prefix_subarray_sum_count:
                num_subarrays_equal_k += prefix_subarray_sum_count[prefix_subarray_sum]
            
            # Store main subarray sum in Hash Table
            prefix_subarray_sum_count[current_sum_of_subarray] = prefix_subarray_sum_count.get(current_sum_of_subarray, 0) + 1
        
        return num_subarrays_equal_k
```
<br />
$Time\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **The algorithm** loops through every element in $nums$.
- **Hence,** big $O$ time complexity is $O(n)$.
<br />
$Space\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **In the worst-case,** every prefix sum is completely unique. 
- **The hash table** will grow to store $n + 1$ distinct prefix sum entries (including the 0 : 1 baseline).
- **Hence,** the big $O$ space complexity is $O(n)$.

### ⚜️&nbsp;&nbsp;Valid Parentheses
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given a string $parentheses\_string$ containing parentheses characters, develop an efficient
algorithm to determine if this string is properly closed and nested. Valid parentheses characters include: \(, \), \[, \], \{, \}.
By properly closed and nested, we mean that every open parentheses has a corresponding closing parentheses and are arranged 
in the correct order without overlap. Meaning that the last open parentheses are closed first, and the first open parentheses
are closed last.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we need to create a Stack class that contains pop, push, and isEmpty
operations and in our main solution function, we initialize an empty stack called $stack$. Then we create a mapping of closing
parentheses with their corresponding opening parentheses. Next we loop character by character in $parentheses\_string$, if the
character in question is in the mapping, which means it is a closing parentheses, then we pop from $stack$ and compare that
character with the corresponding opening parentheses. If they do not match, then return $False$, because there was not a match. 
Otherwise, we push the character in question onto $stack$. After the loop, we check if the stack is empty or not. 
If the stack is empty, this means that $parentheses\_string$ is properly closed and nested, so we return $True$. 
Otherwise, we know that there exists at least one character that did not also match with its corresponding parentheses and so 
we return $False$.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
class Stack:
    def __init__(self):
        self._items = []

    def is_empty(self):
        return len(self._items) == 0

    def push(self, item: str) -> None:
        self._items.append(item)
    
    def pop(self) -> str:
        if self.is_empty():
            return None
        else:
            return self._items.pop()


class Solution:
    def valid_parentheses(self, parentheses_string: str) -> bool:
        stack = Stack()
        parentheses_mapping = {
            ')': '(',
            ']': '[',
            '}': '{'
        }

        for parenthesis in parentheses_string:
            if parenthesis in parentheses_mapping:
                if stack.pop() != parentheses_mapping[parenthesis]:
                    return False
            else:
                stack.push(parenthesis)

        if stack.is_empty():
            return True
        else:
            return False 
```

<br />
**Explanation:**
<br />
- **In the worst-case,** the input string consists entirely of opening parentheses. 
- **The algorithm** will loop through the entirety of the input string of length $n$ exactly once.
- **Hence,** big $O$ time complexity is $O(n)$.
<br />
$Space\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **In the worst-case,** the input string consists entirely of opening parentheses.
- **The algorithm** will push all $n$ characters onto the stack.
- **Hence,** big $O$ space complexity is $O(n)$.

## Queue Problems
<br />
### ⚜️&nbsp;&nbsp;Number of Recent Calls
<br />
**<u>Problem:</u>**&nbsp;&nbsp;You have a RecentCounter class which counts the number of requests within a certain
time frame.
<br />
Implement the RecentCounter class:
- **def __init__(self)** intializes the counter with zero recent requests
- **def ping(self, t: int) -> int** Adds a new request at time $t$, where $t$ represents some time in milliseconds, and returns
the number of requests that has happened in the past $3000$ milliseconds (including the new request). Specifically, return
the number of requests that have happened in the inclusive range $[t - 3000, t]$.
<br />
**Note:** It is guaranteed that every call to **ping** uses a strictly larger value of $t$ than the previous call.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;To solve this problem, we create a custom Queue class with enqueue, dequeue, peek, is_empty,
and size functions. Then in RecentCounter, in the __init__ function, we create a new queue. Then in the ping function, we 
enqueue the input $t$. Then we loop through the queue and dequeue any requests that do not fall in the inclusive range
$[t - 3000, t]$. Then we return the size of the queue.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
class Queue:
    def __init__(self):
        self._items = []

    def enqueue(self, item: int) -> None:
        self._items.append(item)
    
    def dequeue(self) -> int:
        if self.is_empty():
            return None
        else:
            return self._items.pop(0)

    def peek(self) -> int:
        if self.is_empty():
            return None
        else:
            return self._items[0]
        
    def is_empty(self):
        return len(self._items) == 0

    def size(self):
        return len(self._items)


class RecentCounter:
    def __init__(self):
        self.queue = Queue()

    def ping(self, t: int) -> int:
        self.queue.enqueue(t)

        while not self.queue.is_empty() and self.queue.peek() < t - 3000:
            self.queue.dequeue()

        return self.queue.size()
```
<br />
$Time\;Complexity:\;O(1)\;amortized\;per\;ping,\;or\;O(n)\;for\;n\;calls$
<br />
**Explanation:**
<br />
- **When a new ping** arrives, we add the timestamp to the queue.
- **One ping** might trigger multiple removals; however, every single ping is added once and removed at most once 
across the entire lifetime of RecentCounter.
- **Therefore,** big $O$ time complexity amortized per ping is $O(1)$.
<br />
- **The worst-case scenario** is when all $n$ requests happen within the last $3000ms$.
- **In this case,** the while loop designed to dequeue elements outside the inclusive range $[t - 3000, t]$ will 
traverse over all $n$ elements but will not remove any of them.
- **Hence,** big $O$ time complexity for $n$ calls is $O(n)$.
<br />
$Space\;Complexity: O(W),\;where\;W\;is\;the\;maximum\;number\;of\;requests\;inside\;the\;sliding\;window$
<br />
**Explanation:**
<br />
- **The peak memory usage** at any given moment strictly depends on the heaviest traffic spike that fits inside that 3000ms 
window.
- **If there is a maximum** of $W$ pings during the $3000ms$ window, the queue will hold $W$ items.
- **Hence,** big $O$ space complexity is $O(W)$, where $W$ is the maximum number of requests inside the sliding window.

## Tree Problems
<br />
### ⚜️&nbsp;&nbsp;Binary Tree Preorder Traversal
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given the root of a binary tree, return the preorder traversal of its nodes' values.
<br />
**Preorder Traversal (Root &rarr; Left &rarr; Right):** At first the root will be visited. After this, It visits the 
current node first, processes its entire left subtree, and then moves to its right subtree. 
<br />
**<u>Solution:</u>**&nbsp;&nbsp;This problem can be solved recursively and iteratively.
<br />
First the recursive solution is to create a recursive function that takes as input a TreeNode and the list of preorder node
values and to recursively add $current\_node.val$ to the list and then recursively call itself on $current\_node.left$ and then 
on $current\_node.right$. The base case of the recursive function is to return if the node passed in as input is $null$. 
After the recursion is complete, return the list of preorder node values.
<br />
I have implemented the solution recursively:
<br />
```python showLineNumbers
#Recursive Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Solution:
    def preorder_traversal_helper(self, current_node: Optional[Self], preorder_traversal_values: list[int]) -> None:
        if not current_node:
            return
        
        # This recursive order matches the preorder traversal Root -> Left -> Right
        preorder_traversal_values.append(current_node.val)
        self.preorder_traversal_helper(current_node.left, preorder_traversal_values)
        self.preorder_traversal_helper(current_node.right, preorder_traversal_values)

    def preorder_traversal(self, root: Optional[Self]) -> list[int]:
        preorder_traversal_values = []
        self.preorder_traversal_helper(root, preorder_traversal_values)
        return preorder_traversal_values
```
<br />
$Time\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **The algorithm** must visit every single node in the tree exactly once.
- **Therefore,** big $O$ time complexity is $O(n)$.
<br />
$Space\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **Stack Frame:** A new stack frame is created for each recursive call, and the total memory required is proportional 
to the number of recursive calls.
- **The number of** active stack frames is proportional to the height of the tree, because each recursive function call 
corresponds to the algorithm traversing down one level from the current node to a child node (left or right). The algorithm
will accumulate stack frames until it reaches a leaf node. A leaf node has no recursive calls to make, because it has no child
nodes, and so it will not create new stack frames. Since a leaf node has no children, it has no choice but to return and 
this will cause the algorithm to traverse up one level, thereby releasing a stack frame from active use. After one subtree
has been traversed, the algorithm will have released all stack frames accumulated during that subtree traversal before it 
traverses the next subtree.
- **Therefore,** the maximum number of active frames that the program has at any point during its execution is directly 
determined by the height of the tree.
- **In the worst-case,** we have a skewed binary tree, where every node has at most one child node. Instead of branching
out, the tree grows linearly, rendering a configuration of the nodes that yields the maximum possible height $n-1$,
where $n$ represents the number of nodes in the tree.
- *Hence,* the big $O$ space complexity is $O(n)$
<br />
Next, we will transition to the iterative solution. To solve this problem iteratively, we maintain a stack that is a 
running collection of nodes that have not been processed yet. Initially, the stack only has the root node. Then
while the stack is not empty, we pop from the stack and add the value of the popped node to the result, if there is 
a right child, we push it onto the stack, and then if there is a left child, we push it onto the stack. This guarantees
that for a given node, if that node has both left child and right child, the left child will get processed first, since
it is on the top of the stack. Keep looping until the stack is empty and once the loop has finished, return the result.
<br />
I have implemented the solution iteratively:
<br />
```python showLineNumbers
#Iterative Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Stack:
    def __init__(self):
        self._items = []

    def is_empty(self):
        return len(self._items) == 0

    def push(self, item: str) -> None:
        self._items.append(item)
    
    def pop(self) -> str:
        if self.is_empty():
            return None
        else:
            return self._items.pop()

class Solution:
    def preorder_traversal(self, root: Optional[Self]) -> list[int]:
        preorder_traversal_values = []
        stack = Stack()
        stack.push(root)

        while not stack.is_empty():
            node = stack.pop()
            preorder_traversal_values.append(node.val)

            # We first push right onto the stack, because then the stack will have top to bottom order: Left, Right.
            # Root is the first node to be popped, then Left, then Right. 
            # Therefore structure Root -> Left -> Right is maintained.
            if node.right:
                stack.push(node.right)

            if node.left:
                stack.push(node.left)
        
        return preorder_traversal_values
```
<br />
$Time\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **The algorithm** must visit every single node in the tree exactly once.
- **Hence,** big $O$ time complexity is $O(n)$.
<br />
**Explanation:**
<br />
$Space\;Complexity: O(n)$
<br />
- **In the worst-case,** the binary tree is skewed, where the nodes only have right children.
- **The algorithm** will continuously push the right children of the tree onto the stack without popping any of 
them until it reaches the leaf node.
- **Hence,** big $O$ space complexity is $O(n)$.

### ⚜️&nbsp;&nbsp;Binary Tree Inorder Traversal
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given the root of a binary tree, return the inorder traversal of its nodes' values.
<br />
**Inorder Traversal (Left &rarr; Root &rarr; Right):** At first process the left subtree. Then visit the root node.
Lastly, process the right subtree.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;This problem can be solved recursively and iteratively.
<br />
First the recursive solution is to create a recursive function that takes as input a TreeNode called $current\_node$ and the list 
of inorder node values and to perform a recursive call on $current\_node.left$. Then add the input node's value to the list of 
inorder node values. Lastly, perform a recursive call on $current\_node.right$. The base case is to return when the input node 
is $null$. After the recursion is complete, return the list of inorder node values.
<br />
I have implemented the recursive solution below:
<br />
```python showLineNumbers
#Recursive Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Solution:
    def inorder_traversal_helper(self, current_node: Optional[Self], inorder_traversal_values: list[int]) -> None:
        if not current_node:
            return
        
        # This recursive order matches inorder traversal: Left -> Root -> Right
        self.inorder_traversal_helper(current_node.left, inorder_traversal_values)
        inorder_traversal_values.append(current_node.val)
        self.inorder_traversal_helper(current_node.right, inorder_traversal_values)
    
    def inorder_traversal(self, root: Optional[Self]) -> list[int]:
        inorder_traversal_values = []
        self.inorder_traversal_helper(root, inorder_traversal_values)
        return inorder_traversal_values
```

- **The number of** active stack frames is proportional to the height of the tree, because each recursive function call

has been traversed, the algorithm will have released all stack frames accumulated during that subtree traversal before it 
traverses the next subtree.

determined by the height of the tree.

Next, we will transition to the iterative solution. To solve this problem iteratively, we maintain a stack that is a 
running collection of nodes that have not been processed yet. Initially, the stack is empty and we have a $current\_node$
pointer set to the root node. We run a nested while loop while there are still nodes left to be processed. We continuously
push left child nodes onto the stack. Once our pointer is null, we pop from the stack and set our $current\_node$ pointer to 
the popped node. Add that node's value to the result. Then set $current\_node$ equal to its right child. And repeat until
there are no more nodes left to process and return the result.

```python showLineNumbers
#Iterative Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Stack:
    def __init__(self):
        self._items = []

    def is_empty(self):
        return len(self._items) == 0

    def size(self):
        return len(self._items)

    def push(self, item: str) -> None:
        self._items.append(item)
    
    def pop(self) -> str:
        if self.is_empty():
            return None
        else:
            return self._items.pop()

class Solution:
    def inorder_traversal(self, root: Optional[Self]) -> list[int]:

        # stack holds running collection of nodes not yet processed.
        stack = Stack()

        # The list of inorder traversal values.
        inorder_traversal_values = []

        # The current node initially set as root.
        current_node = root

        # If current_node is not null or stack size is non empty, there are still nodes not yet processed.
        while current_node or not stack.is_empty():
            # We always process left children first so we continuously push left children 
            # onto the stack until there are no more on that branch.
            while current_node:
                stack.push(current_node)
                current_node = current_node.left
            
            # This structure ensures that the current_node is the leftmost child
            # of this branch, that has not been processed yet.
            # All of it's left children (if any) have been processed already.
            # And so we then process this current_node.
            # And then now it is free to examine it's right children branch (if any).
            # Thus keeping with the Left -> Root -> Right structure.
            current_node = stack.pop()
            inorder_traversal_values.append(current_node.val)
            current_node = current_node.right
        
        return inorder_traversal_values
```

### ⚜️&nbsp;&nbsp;Binary Tree Postorder Traversal
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given the root of a binary tree, return the postorder traversal of its nodes' values.
<br />
**Postorder Traversal (Left &rarr; Right &rarr; Root):** At first process the left subtree. Then process the right subtree.
Lastly, visit the root node.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;This problem can be solved recursively and iteratively.
<br />
First the recursive solution is to create a recursive function that takes as input a TreeNode called $current\_node$ and the 
list of postorder traversal values. First perform a recursive call on $current\_node.left$. Then perform a recursive call on 
$current\_node.right$. Lastly, append the input node's value to the list of postorder traversal values. The base case is when
the input node is $null$, then return. After the recursion is complete, return the list of postorder traversal values.
<br />
I have implemented the recursive solution below:
<br />
```python showLineNumbers
#Recursive Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Solution:
    def postorder_traversal_helper(self, current_node: Optional[Self], postorder_traversal_values: list[int]) -> None:
        if not current_node:
            return
        
        # This recursive order matches postorder traversal Left -> Right -> Root
        self.postorder_traversal_helper(current_node.left, postorder_traversal_values)
        self.postorder_traversal_helper(current_node.right, postorder_traversal_values)
        postorder_traversal_values.append(current_node.val)
    
    def postorder_traversal(self, root: Optional[Self]) -> list[int]:
        postorder_traversal_values = []
        self.postorder_traversal_helper(root, postorder_traversal_values)
        return postorder_traversal_values
```

- **The number of** active stack frames is proportional to the height of the tree, because each recursive function call

Next, we will transition to the iterative solution. There are two different ways to solve this problem iteratively.
One way is to use two stacks. The other way is to use one stack.
<br />
To solve this problem iteratively using two stacks, we maintain two stacks $stack1$ and
$stack2$. $stack1$ is designed to store the reverse of the postorder traversal which is Root &rarr; Right &rarr; Left.
$stack2$ is designed to hold the reverse of $stack1$, which is our postorder traversal Left  &rarr; Right  &rarr; Root.
We begin with $stack1$ holding the root node, and $stack2$ is empty. We loop while $stack1$ is not empty. 
We pop from $stack1$ and store it in a pointer called $current\_node$ and push that node
onto $stack2$. By popping from $stack1$ and pushing onto $stack2$, we are making $stack2$ the reverse the order of $stack1$. 
Then if the $current.left$ then push $current.left$ onto $stack1$. If $current.right$, then push $current.right$ onto $stack1$.
Why do we push $.left$ first and then $.right$? It is because of the LIFO property of stack. This will result in 
$stack2$ having the order from bottom to top: Root &rarr; Right &rarr; Left. Then when $stack2$ pops, it will have the order
Left &rarr; Right &rarr; Root, which is the order that we want. Keep repeating this loop until $stack1$ is empty, which means
that all of the nodes have been visited once, and then while $stack2$ is not empty, push the popped values into the 
postorder_traversal_values array and after the loop return postorder_traversal_values.

```python showLineNumbers
#Iterative Two Stack Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Stack:
    def __init__(self):
        self._items = []

    def is_empty(self):
        return len(self._items) == 0

    def size(self):
        return len(self._items)

    def push(self, item: str) -> None:
        self._items.append(item)
    
    def pop(self) -> str:
        if self.is_empty():
            return None
        else:
            return self._items.pop()

class Solution:
    def postorder_traversal(self, root: Optional[Self]) -> list[int]:

        # Maintains reverse of postorder traversal with top to bottom order: Root, Right, Left.
        stack1 = Stack()

        # Maintains reverse of stack1 with top to bottom order: Left, Right, Root. 
        # Because of LIFO property, Left is on the top of the stack.
        stack2 = Stack()

        # Stores values of the postorder_traversal
        postorder_traversal_values = []

        # Initially stack1 will have root, making root be placed at the bottom of stack2.
        stack1.push(root)

        while not stack1.is_empty():
            current_node = stack1.pop()

            # Pushing the popped value of stack1 onto stack2 reverses the order of stack1
            stack2.push(current_node)

            # We want to push left onto stack1 first. That way stack1 holds top to bottom: Right, Left.
            # So then stack2 will have the reverse top to bottom order: Left, Right, which is what we want because LIFO.
            if current_node.left:
                stack1.push(current_node.left)

            if current_node.right:
                stack1.push(current_node.right)
        
        # stack2 will contain nodes in top to bottom order: Left, Right, Root, which is what we want because LIFO.
        while not stack2.is_empty():
            current_node = stack2.pop()
            postorder_traversal_values.append(current_node.val)

        return postorder_traversal_values
```

Next, we will transition to the iterative solution of this problem using only one stack. This problem is challenging
because the algorithm must visit both left subtree and right subtree before evaluating the root. Therefore, the core 
idea behind the one stack solution of this problem is that for every node that we encounter that is not a left child, 
we need to evaluate if this node is the parent node's right child. If so, then the algorithm must traverse down the 
parent's right subtree, before the algorithm can evaluate the parent. Only after the parent's right child has been popped 
from the stack, can we say that the parent node's right subtree has been evaluated and only then can we evaluate the 
parent node.

```python showLineNumbers
#Iterative One Stack Solution
from typing import Self, Optional

class TreeNode:
    def __init__(self, val: int = 0, left: Optional[Self] = None, right: Optional[Self] = None):
        self.val = val
        self.left = left 
        self.right = right

class Stack:
    def __init__(self):
        self._items = []

    def is_empty(self):
        return len(self._items) == 0

    def size(self):
        return len(self._items)

    def peek(self):
        return self._items[-1]

    def push(self, item: str) -> None:
        self._items.append(item)
    
    def pop(self) -> str:
        if self.is_empty():
            return None
        else:
            return self._items.pop()

class Solution:
    def postorder_traversal(self, root: Optional[Self]) -> list[int]:

        # Maintains a running collection of nodes not yet processed
        stack = Stack()

        # Stores values of the postorder_traversal
        postorder_traversal_values = []

        # Set currrent_node equal to the root
        current_node = root

        while current_node or not stack.is_empty():
            # If current_node is pointing to a node, push it onto the stack and make current_node its left child.
            # Left child because we want to traverse down the left child branch (if any) until it has been exhausted.
            if current_node:
                stack.push(current_node)
                current_node = current_node.left
            # After left child branch (if any) has been exhausted, 
            # check into right child branch (if any).
            elif stack.peek().right:
                current_node = stack.peek().right
            # Left child branch (if any) and right child branch (if any) 
            # have both been exhausted. Time to pop from the stack.
            else:
                evaluated_node = stack.pop()
                postorder_traversal_values.append(evaluated_node.val)

                # If the currently evaluated node is the right child the parent, 
                # that means that the left and right subtree of the parent have been evaluated.
                # And so the parent can be popped. Continue popping while this is the case,
                # and stack is not empty.
                while not stack.is_empty() and evaluated_node == stack.peek().right:
                    evaluated_node = stack.pop()
                    postorder_traversal_values.append(evaluated_node.val)
            
        return postorder_traversal_values
```

## Heap Problems

### ⚜️&nbsp;&nbsp;Heap Sort
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given an unsorted array of integers, implement the Heap Sort algorithm 
and return the array sorted.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;Heap Sort is an efficient, comparison-based sorting algorithm that uses a Binary Heap 
to sort elements. A Binary Heap is an abstraction adhering to a conceptual set of rules, while the underlying data is 
structured most typically as an array. A Binary Heap leverages an array to implicitly represent a Complete Binary Tree, 
mapping parent-child relationships through simple index arithmetic rather than physical pointers. A Complete Binary Tree is a 
Binary Tree that is completely filled in every level with the possible exception of the last level. The last level can be filled, 
but it is not required. If there are elements in the last level of the tree, and the last level of the tree is not completely 
filled, then the elements in the last level of the tree must be filled from left to right and there cannot be any gaps. 
A key concept to understand is the Array to Tree mapping. So for any element in the heap at index $i$, its left child (if exists)
is at index $2i + 1$, its right child (if exists) is at index $2i + 2$ and its parent (if exists) is at index 
$\lfloor \frac{i-1}{2} \rfloor$. In this implementation, the first step that we will need to do is to turn our unsorted array 
into a Max Heap. Max Heap is a special type of heap where the value of any given node in the heap is greater than or equal to 
the values of its children (if any). To turn this unsorted array into a Max Heap, we need to implement a heapify function. 
The heapify function rearrnges the elements of the array such that the properties of Max Heap are maintained: for every node, 
it's value is greater than or equal to that of its children (if any). Since leaf nodes do not have children, we do not run the 
heapify function on leaf nodes. We run the heapify function starting with the last non-leaf node and work our way backwards up 
to the root. After the array has been turned into a Max Heap, the algorithm will perform Extract Max, which swaps the root with 
the last element that has not already been extracted, putting the max after all of the elements that have not yet been extracted
but before all of the elements that have already been extracted. We then perform heapify on the root, which sifts the root 
down to its correct position in the Max Heap. Keep repeating this process for all elements that have not already been extracted 
until there is only one element left in the Max Heap. Then after that the array is now sorted and can be returned.
<br />
This solution can be implemented recursively and iteratively.
<br />
I have implemented the recursive solution below:
<br />
```python showLineNumbers
# Recursive Solution
class Solution:
    def max_heapify(self, arr: list[int], heap_size: int, current_index: int) -> None:
        # The max_heapify function wants to determine which among [root, left child, right child] is the largest
        # If the largest is root, we return
        # If the largest is left child or right child, 
        # we swap the largest value with the root's value and call max_heapify
        # on the affected subtree (left or right)
        largest_index = current_index
        left_child_index = 2 * current_index + 1
        right_child_index = 2 * current_index + 2

        # Check if left child exists and is larger than largest so far
        # If yes to both, then set largest index as left child index
        if left_child_index < heap_size and arr[left_child_index] > arr[largest_index]:
            largest_index = left_child_index

        # Check if right child exists and is larger than largest so far
        # If yes to both, then set largest index as right child index
        if right_child_index < heap_size and arr[right_child_index] > arr[largest_index]:
            largest_index = right_child_index

        # If the largest is not the root, we swap root's value with the largest's value
        # and recursively call max_heapify on the affected sub-tree (left or right).
        # If the largest is the root, this is the base case, and so we return.
        if largest_index != current_index:
            # Swap the value of root with the value of largest among [left child, right child].
            arr[current_index], arr[largest_index] = arr[largest_index], arr[current_index]

            # Recursively call max_heapify on the affected subtree (left or right).
            self.max_heapify(arr, heap_size, largest_index)


    def heap_sort(self, arr: list[int]) -> list[int]:
        heap_size = len(arr)

        # Build Max Heap
        # We heapify every node starting with the last non-leaf node and work our way backwards up to the root.
        for i in range((heap_size - 2) // 2, -1, -1):
            self.max_heapify(arr, heap_size, i)

        # Extract Max
        for i in range(heap_size - 1, 0, -1):
            # Swap root with last element that has not already been extracted.
            arr[0], arr[i] = arr[i], arr[0]

            # Call heapify on the root, sifting it down to its correct position in the Max Heap.
            self.max_heapify(arr, i, 0)

        return arr
```
<br />
$Time\;Complexity: O(nlog\;n)$
<br />
**Explanation:**
<br />
- **The time complexity** of this algorithm can be divided into two parts.
- **Part 1 is Time Complexity to Build Max Heap:**
- **To build a Max Heap,** the algorithm calls max_heapify on all non-leaf nodes to the root.
- **The time required** to max_heapify a node depends on the height of the heap, because max_heapify
sifts a node down from the root level by level to its correct position. So as the number of levels, or the
height of the heap increases, the time resources required will also increase.
- **Therefore,** a single max_heapify operation takes $O(h)$ time.
- **Since a heap is a Complete Binary Tree,** at height $h$, or another way to think of it is at level $h$ in the Heap,
the maximum number of nodes that can be at that level or height is: $\lceil \frac{n}{2^{h + 1}} \rceil$.
- **Then we can say** that the total time to build a Max Heap is: 
$$
\sum_{h=1}^{\lfloor log\;n \rfloor} \frac{n}{2^{h + 1}}\;•\;O(h)
$$
(we begin the summation at $h = 1$ because we ignore the level with the leaf nodes)
<br />
- **We can factor out** $\frac{n}{2}$. Leading to:
$$
\frac{n}{2}\;•\;\sum_{h=1}^{\lfloor log\;n \rfloor} \frac{O(h)}{2^{h}}
$$
<br />
- **By applying** big $O$ notation, terms like $\frac{1}{2}$ get absorbed and since big $O$ is an asymptotic upper bound,
we can extend the summation to infinity, leading to:
$$
O(n\;•\;\sum_{h=1}^{\infty} \frac{h}{2^{h}})
$$
<br />
- **Evaluating the geometric series,** we get:
$$
S = \sum_{h=1}^{\infty} \frac{h}{2^{h}} = \frac{1}{2^{1}} + \frac{2}{2^{2}} + \frac{3}{2^{3}} + \frac{4}{2^{4}} + ... 
$$
<br />
- **We then multiply** the whole equation by $\frac{1}{2}$ to get:
$$
\frac{1}{2}\;•\;S = \frac{1}{2^{2}} + \frac{2}{2^{3}} + \frac{3}{2^{4}} + ... 
$$
<br />
- **Subtracting** $S - \frac{1}{2}\;•\;S$ yields:
$$
S - \frac{1}{2}\;•\;S = \frac{1}{2^{1}} + (\frac{2}{2^{2}} - \frac{1}{2^{2}}) + (\frac{3}{2^{3}} - \frac{2}{2^{3}}) + (\frac{4}{2^{4}} - \frac{3}{2^{4}}) + ... 
$$
<br />
- **This equation** simplifies to:
$$
\frac{1}{2}\;•\;S = \frac{1}{2} + \frac{1}{4} + \frac{1}{8} + \frac{1}{16} + ... 
$$
<br />
- **The right side** of this equation is an infinite geometric series, where the first term $a$ is $\frac{1}{2}$
and the common ratio $r$ is $\frac{1}{2}$. We can use this formula $\frac{a}{1 - r}$:
$$
\frac{1}{2}\;•\;S = \frac{\frac{1}{2}}{1 - \frac{1}{2}} = \frac{\frac{1}{2}}{\frac{1}{2}} = 1
$$
<br />
- **Solving for** $S$ we get:
$$
S = 2
$$
<br />
- **Plugging** S back into the big $O$ formula from before, we get:
$$
O(n\;•\;2) = O(n)
$$
<br />
- **Therefore,** big $O$ time complexity for building the Max Heap is $O(n)$.
<br />
- **Phase 2 is Sorting the Elements**
- **The time required** to max_heapify a node depends on the height of the heap, because max_heapify
sifts a node down from the root level by level to its correct position. So as the number of levels, or the
height of the heap increases, the time resources required will also increase.
- **Therefore,** a single max_heapify operation takes $O(h) = O(log\;n)$ time.
- **The loop to sort the elements** runs $n - 1$ times.
- **Therefore,** the time required to sort the elements is $O((n - 1)\;•\;log\;n) = O(nlog\;n)$.
<br />
- **Putting the two phases together,** we get total time complexity: $O(n) + O(nlog\;n) = O(nlog\;n)$.
- **Hence,** the big $O$ time complexity is $O(nlog\;n)$.
<br />
$Space\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **Stack Frame:** A new stack frame is created for each recursive call, and the total memory required is proportional 
to the number of recursive calls.
- **The number of active stack frames** is proportional to the height of the heap. Because the recursive function max_heapify 
sifts a node down from the root, level by level, to its correct position. And on every level during the process,
max_heapify makes a recursive call to itself. In the worst-case, a root node will be sifted down all the way to the bottom
level as a leaf node.
- **Therefore,** the worst-case maximum number of stack frames is $O(h) = O(log\;n)$.
- **Hence,** the big $O$ space complexity is $O(log\;n)$.
<br />
Now that we have explained the recursive solution, we will now transition to the iterative solution. The iterative solution
is almost the same as the recursive solution, but for the heapify function, instead of recursively calling itself with the
index of the largest child, it will use a while loop instead and when $largest\_index != current\_index$ it will 
swap the values of the arr at $current\_index$ and $largest\_index$ and set the $current\_index = largest\_index$.
It will keep looping until the $largest\_index == current\_index$ at which point it will break out of the loop.
<br />
I have implemented the iterative solution below:
<br />
```python showLineNumbers
# Iterative Solution
class Solution:
    def max_heapify(self, arr: list[int], heap_size: int, current_index: int) -> None:
        # The max_heapify function wants to determine which among [root, left child, right child] is the largest
        # If the largest is root, we return
        # If the largest is left child or right child, 
        # we swap the largest value with the root's value and call max_heapify
        # on the affected subtree (left or right)
        while True:
            largest_index = current_index
            left_child_index = 2 * current_index + 1
            right_child_index = 2 * current_index + 2

            # Check if left child exists and is larger than largest so far
            # If yes to both, then set largest index as left child index
            if left_child_index < heap_size and arr[left_child_index] > arr[largest_index]:
                largest_index = left_child_index

            # Check if right child exists and is larger than largest so far
            # If yes to both, then set largest index as right child index
            if right_child_index < heap_size and arr[right_child_index] > arr[largest_index]:
                largest_index = right_child_index

            # If the largest is not the root, we swap root's value with the largest's value
            # and we set current_index equal to largest_index.
            # If the largest is the root, we break out of the loop.
            if largest_index != current_index:
                # Swap the value of root with the value of largest among [left child, right child].
                arr[current_index], arr[largest_index] = arr[largest_index], arr[current_index]
                current_index = largest_index
            else:
                break


    def heap_sort(self, arr: list[int]) -> list[int]:
        heap_size = len(arr)

        # Build Max Heap
        # We heapify every node starting with the last non-leaf node and work our way backwards up to the root.
        for i in range((heap_size - 2) // 2, -1, -1):
            self.max_heapify(arr, heap_size, i)

        # Extract Max
        for i in range(heap_size - 1, 0, -1):
            # Swap root with last element that has not already been extracted.
            arr[0], arr[i] = arr[i], arr[0]

            # Call heapify on the root, sifting it down to its correct position in the Max Heap.
            self.max_heapify(arr, i, 0)

        return arr
```
<br />
$Time\;Complexity: O(nlog\;n)$
<br />
**Explanation:**
<br />
- **The time complexity** of this algorithm can be divided into two parts.
- **Part 1 is Time Complexity to Build Max Heap:**
- **To build a Max Heap,** the algorithm calls max_heapify on all non-leaf nodes to the root.
- **The time required** to max_heapify a node depends on the height of the heap, because max_heapify
sifts a node down from the root level by level to its correct position. So as the number of levels, or the
height of the heap increases, the time resources required will also increase.
- **Therefore,** a single max_heapify operation takes $O(h)$ time.
- **Since a heap is a Complete Binary Tree,** at height $h$, or another way to think of it is at level $h$ in the Heap,
the maximum number of nodes that can be at that level or height is: $\lceil \frac{n}{2^{h + 1}} \rceil$.
- **Then we can say** that the total time to build a Max Heap is: 
$$
\sum_{h=1}^{\lfloor log\;n \rfloor} \frac{n}{2^{h + 1}}\;•\;O(h)
$$
(we begin the summation at $h = 1$ because we ignore the level with the leaf nodes)
<br />
- **We can factor out** $\frac{n}{2}$. Leading to:
$$
\frac{n}{2}\;•\;\sum_{h=1}^{\lfloor log\;n \rfloor} \frac{O(h)}{2^{h}}
$$
<br />
- **By applying** big $O$ notation, terms like $\frac{1}{2}$ get absorbed and since big $O$ is an asymptotic upper bound,
we can extend the summation to infinity, leading to:
$$
O(n\;•\;\sum_{h=1}^{\infty} \frac{h}{2^{h}})
$$
<br />
- **Evaluating the geometric series,** we get:
$$
S = \sum_{h=1}^{\infty} \frac{h}{2^{h}} = \frac{1}{2^{1}} + \frac{2}{2^{2}} + \frac{3}{2^{3}} + \frac{4}{2^{4}} + ... 
$$
<br />
- **We then multiply** the whole equation by $\frac{1}{2}$ to get:
$$
\frac{1}{2}\;•\;S = \frac{1}{2^{2}} + \frac{2}{2^{3}} + \frac{3}{2^{4}} + ... 
$$
<br />
- **Subtracting** $S - \frac{1}{2}\;•\;S$ yields:
$$
S - \frac{1}{2}\;•\;S = \frac{1}{2^{1}} + (\frac{2}{2^{2}} - \frac{1}{2^{2}}) + (\frac{3}{2^{3}} - \frac{2}{2^{3}}) + (\frac{4}{2^{4}} - \frac{3}{2^{4}}) + ... 
$$
<br />
- **This equation** simplifies to:
$$
\frac{1}{2}\;•\;S = \frac{1}{2} + \frac{1}{4} + \frac{1}{8} + \frac{1}{16} + ... 
$$
<br />
- **The right side** of this equation is an infinite geometric series, where the first term $a$ is $\frac{1}{2}$
and the common ratio $r$ is $\frac{1}{2}$. We can use this formula $\frac{a}{1 - r}$:
$$
\frac{1}{2}\;•\;S = \frac{\frac{1}{2}}{1 - \frac{1}{2}} = \frac{\frac{1}{2}}{\frac{1}{2}} = 1
$$
<br />
- **Solving for** $S$ we get:
$$
S = 2
$$
<br />
- **Plugging** S back into the big $O$ formula from before, we get:
$$
O(n\;•\;2) = O(n)
$$
<br />
- **Therefore,** big $O$ time complexity for building the Max Heap is $O(n)$.
<br />
- **Phase 2 is Sorting the Elements**
- **The time required** to max_heapify a node depends on the height of the heap, because max_heapify
sifts a node down from the root level by level to its correct position. So as the number of levels, or the
height of the heap increases, the time resources required will also increase.
- **Therefore,** a single max_heapify operation takes $O(h) = O(log\;n)$ time.
- **The loop to sort the elements** runs $n - 1$ times.
- **Therefore,** the time required to sort the elements is $O((n - 1)\;•\;log\;n) = O(nlog\;n)$.
<br />
- **Putting the two phases together,** we get total time complexity: $O(n) + O(nlog\;n) = O(nlog\;n)$.
- **Hence,** the big $O$ time complexity is $O(nlog\;n)$.

$Space\;Complexity: O(1)$
<br />
**Explanation:**
<br />
- **The algorithm** only needs to store a few integer variables resulting in constant auxiliary memory usage regardless of size
of inputs. 
- **Hence,** the big $O$ space complexity is: $O(1)$.

### ⚜️&nbsp;&nbsp;Find K Pairs with Smallest Sums
<br />
**<u>Problem:</u>**&nbsp;&nbsp;You are given two integer arrays $nums1$ and $nums2$ sorted in non-descreasing order and an
integer $k$. 
<br />
Define a pair $(u, v)$ which consists of one element from the first array and one element from the second array.
<br />
Return the $k$ pairs $(u_1, v_1), (u_2, v_2), ..., (u_k, v_k)$ with the smallest sums.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;Since $nums1$ and $nums2$ are sorted, the absolute smallest sum is guaranteed to be the 
sum of $nums1[0]$ and $nums2[0]$. Next we will either want to move the index of $nums1$ forward by 1 and keep the index of 
$nums2$ the same or move the index of $num2$ forward by 1 and keep the index of $nums1$ the same. Instead of comparing the 
possible candidates manually, we will use a min-heap to arrange the elements such that the $(u, v)$ pair with the smallest
sum is at the top of the tree. Each node of the heap will contain 3 items: the sum of $(u, v)$, the index of $u$, and the index
of $v$. By utilizing this approach, we may encounter a scenario where we view the same $(u, v)$ more than once, and so we 
maintain a set to keep track of all $(u, v)$ that we have visited so far. Continue to push new candidates onto the heap
and extract elements from the top of the heap until we have reached $k$ pairs, and then stop.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
import heapq

class Solution:
    def k_smallest_pairs(self, nums1: list[int], nums2: list[int], k: int) -> list[int]:
        if not nums1 or not nums2 or k <= 0:
            return []
        
        smallest_pairs = []
        visited_pairs = set()
        # Initialize the heap with the first (u, v) being (0, 0)
        # Each heap element contains 3 items: the sum of u & v, the index of u, and the index of v.
        min_heap = [[nums1[0] + nums2[0], 0, 0]]

        # Loop while there are nodes in the heap and we have not yet reached k pairs
        while min_heap and len(smallest_pairs) < k:
            # Pop the top element from the heap
            sum, idx_1, idx_2 = heapq.heappop(min_heap)
            # Add the values nums1[idx_1] and nums2[idx_2] to the result
            smallest_pairs.append([nums1[idx_1], nums2[idx_2]])

            # Work on the potential candidate (idx_1 + 1, idx_2)
            candidate_idx_1 = idx_1 + 1
            candidate_idx_2 = idx_2
            # Check to see if idx_1 + 1 is in bounds and that the pair (idx_1 + 1, idx_2)
            # has not yet been visited. If so, add the pair to the heap and also add the pair to 
            # the set of visited pairs.
            if candidate_idx_1 < len(nums1) and (candidate_idx_1, candidate_idx_2) not in visited_pairs:
                heapq.heappush(min_heap, [nums1[candidate_idx_1] + nums2[candidate_idx_2], candidate_idx_1, candidate_idx_2])
                visited_pairs.add((candidate_idx_1, candidate_idx_2))

            # Work on the potential candidate (idx_1, idx_2 + 1)
            candidate_idx_1 = idx_1
            candidate_idx_2 = idx_2 + 1
            # Check to see if idx_2 + 1 is in bounds and that the pair (idx_1, idx_2 + 1)
            # has not yet been visited. If so, add the pair to the heap and also add the pair to 
            # the set of visited pairs.
            if candidate_idx_2 < len(nums2) and (candidate_idx_1, candidate_idx_2) not in visited_pairs:
                heapq.heappush(min_heap, [nums1[candidate_idx_1] + nums2[candidate_idx_2], candidate_idx_1, candidate_idx_2])
                visited_pairs.add((candidate_idx_1, candidate_idx_2))
        
        return smallest_pairs
```
<br />
$Time\;Complexity: O(klog\;k)$
<br />
**Explanation:**
<br />
- **The while loop** runs at most $k$ times because for every iteration of the while loop, the algorithm is adding a 
new pair to the result.
- **For every iteration** of the while loop, the algorithm is popping from the min-heap. And pushing two new candidates 
onto the min-heap. 
- **The size of the min-heap** is upper bounded by $O(k)$ since there are at most $k$ iterations and in
each iteration there is a constant amount of nodes being added/removed.
- **Therefore,** the time complexity of popping from the min heap and pushing two new candidates onto the min-heap 
is upper bounded by $O(log\;k)$.
- **In conclusion,** we have $k$ iterations and $O(log\;k)$ amount of work per iteration. Therefore, the big $O$ time
complexity is $O(klog\;k)$.
<br />
$Space\;Complexity: O(k)$
<br />
**Explanation:**
<br />
- **The size of the min-heap** is upper bounded by $O(k)$ since there are at most $k$ iterations and in
each iteration there is a constant amount of nodes being added/removed.
- **The size of the set** used to track visited $(u, v)$ pairs is also upper bounded by $O(k)$ since we are 
adding at most two pairs to the set per iteration for $k$ iterations.
- **Therefore,** big $O$ space complexity is $O(k)$.

### ⚜️&nbsp;&nbsp;Find all Prime numbers less than or equal to n (Sieve of Eratosthenes)
<br />
**<u>Problem:</u>**&nbsp;&nbsp;Given a positive integer $n$, develop an efficient algorithm to calculate and return all 
prime numbers less than or equal to $n$. A prime number is a number greater than $1$ that has no positive divisors other 
than $1$ and itself.
<br />
**<u>Solution:</u>**&nbsp;&nbsp;First, we must begin by explaining how to determine if a number is prime.<br />
If $n$ is composite (not prime), it can be factored into two numbers $a$ and $b$ such that
$n = a\;•\;b$.<br />If both $a > \sqrt{n}\;and\;b > \sqrt{n},\;then\;a\;•\;b > n$. 
Similarly if $a < \sqrt{n}\;and\;b < \sqrt{n},\;then\;a\;•\;b < n$.<br />Therefore either $a \leq \sqrt{n}\;and\;b \geq \sqrt{n}$,
or $a \geq \sqrt{n}\;and\;b \leq \sqrt{n}$.<br />Either way, at least one of the factors of $n$ must be less than or equal 
to $\sqrt{n}$. We can use this information to find out if a number is prime or not.
We can loop starting from the smallest prime number $2$ to $\sqrt{n}$. If there exists such a factor, that divides into
$n$ evenly we will know that $n$ is not prime. But if after the loop no such factor is found, we will know that $n$ is prime.
<br />
Having understood this, we will now discuss the **Sieve of Eratosthenes algorithm**. The basic idea of this algorithm is to take 
any prime number $p$. The multiples of $p$, such as $2p, 3p, 4p, 5p, ...$ will not be prime, because they are all divisible by
$p$. So to find all of the prime numbers from $1$ to $n$, I will create an array of size $n+1$, call it $primes$,
and each element of $primes$ will represent a number starting from $0$. So the element at index $0$ will represent $0$, 
the element at index $1$ will represent $1$, and so on. The value of each element will be if this number is prime or not. 
So it will be $True$ if the number is prime, and $False$ if the number is not prime. To start, we will set the value of every 
element in $primes$ to $True$. Then we will set the values of the elements at index $0$ and index $1$ to $False$, because $0$ 
is not prime and $1$ is not prime. Then we loop from $2$ to $\sqrt{n}$. We loop to $\sqrt{n}$ because any composite number 
$k$, where $k \leq n$, will have a factor less than or equal to $\sqrt{n}$. So then by the time the loop ends at $\sqrt{n}$, 
all composite numbers $k \leq n$ will have been marked $False$. If $primes[i]$, where $i$ is the current index, is $True$, then mark
all multiples of $i$ starting from $i^2$ to $n$ as $False$. We begin with $i^2$ because all composite numbers previous to 
$i^2$ would have already been marked as $False$, because those values will contain prime factors that are less than $i$, 
and so they will have been covered in a previous iteration of the loop. After the loop, print a list of all indices where 
the value in $primes$ at that index is $True$.
<br />
I have implemented the solution below:
<br />
```python showLineNumbers
import math

class Solution:
    def sieve_of_eratosthenes(self, n: int) -> list[int]:
        primes = [True] * (n + 1)
        primes[0] = False
        primes[1] = False

        primes_index = 2
        while primes_index <= math.sqrt(n):
            if primes[primes_index] == True:
                multiples_index = primes_index*primes_index
                while multiples_index <= n:
                    primes[multiples_index] = False
                    multiples_index += primes_index
            primes_index += 1
        
        return [p for p in range(n+1) if primes[p] == True] 
```
<br />
$Time\;Complexity: O(nloglog\;n)$
<br />
**Explanation:**
<br />
- **For every prime** $p$, the algorithm crosses out its multiples up to n. This takes $\frac{n}{p}$ operations,
because for any generic prime $p$, the algorithm crosses out $p, 2p, 3p,...,n$. Therefore, there are $\frac{n}{p}$
cross outs to perform.
- **Summing up** the operations yields $\sum_{p \leq n} \frac{n}{p}$, which simplifies to $n\sum_{p \leq n} \frac{1}{p}$. 
- **Mertens' Theorem** states that $\sum_{p \leq n} \frac{1}{p}$ grows proportionally to $log(log\;n)$. 
- **Hence,** big $O$ time complexity is $O(nloglog\;n)$
<br />
$Space\;Complexity: O(n)$
<br />
**Explanation:**
<br />
- **The algorithm** uses a boolean array of size $n$. 
- **Hence,** the big $O$ space complexity is $O(n)$
